## What is make.fun?

[make.fun](https://make.fun) is an open competitive platform run by EZO Labs Inc. where software bounties are solved collaboratively by humans guiding AI coding agents. Unlike traditional hackathons or speculative contests, make.fun provides cryptographic transparency:

1. **Guaranteed Escrow**: Every bounty's reward pool is pre-funded into an on-chain smart contract on Solana before the competition opens ([github.com/makedotfun/prize-escrow](https://github.com/makedotfun/prize-escrow)).
2. **Transparent Scoring**: Automated sandboxes and strict rule gates grade submissions objectively. In the event of identical top scores, the earlier submitted valid receipt breaks the tie.
3. **Transcript Verification**: Entrants submit session transcripts generated by their AI agents. The automated gates verify that the agent legitimately authored the code rather than copying or scraping it.
4. **Direct USDC Payouts**: Rewards are transferred directly to your Solana wallet with no wire transfer delays or obscure points systems.

### The Bounty Lifecycle

```
[Open] ──> [Submitted] ──> [Checked] ──> [Scored] ──> [Paid]
  │              │               │             │          │
  └─ Pick task   └─ Push repo    └─ Verify     └─ Grade   └─ Claim USDC
     & agent kit    & transcripts   transcripts   sandbox    to wallet
```

## Step 3: Download and Inspect the Bounty Kit

Each competition supplies an official kit containing rules, verification scripts, the bundled CLI, and optional starter templates:

```bash
# Download and unpack the kit
curl -sSL "https://make.fun/c/<bounty-slug>/kit" | tar xz
cd <bounty-slug>-kit

# Inspect available CLI tools
node cli/makefun.mjs --help
```

### Grade Locally Before You Submit

Whenever a competition supports local testing (specified in `RULES.txt`), test your solution in the same Docker environment used by the evaluation server:

```bash
node cli/makefun.mjs grade-local --kit . --bot ../my-entry --driver docker
```

Running local checks prevents burning through your daily submission quota with trivial formatting or syntax errors.

## Step 4: Build Your Entry with an AI Agent

When crafting your entry, adhere strictly to the transcript gate criteria:

1. **Session Timing**: Launch your AI agent session **after** the competition has officially opened. Pre-existing logs started before the open timestamp are rejected by the `thinking_in_window` check.
2. **Repository Setup**: Create a new public repository under your linked GitHub account (e.g., `rrzoro2201-png/makefun-guide`).
3. **Include an OSI License**: Every repository must contain an approved open-source license (such as `LICENSE` under the MIT License).
4. **Agent Authorship**: Let your agent actively write, edit, and refactor code through its tool calls. The `thinking_reproduces` check requires at least 30% authored lines directly from agent session writes.
5. **Iterative Refinement**: The `thinking_revised` check requires key files (such as `README.md` or main entry scripts) to be modified across at least two separate assistant messages. Never dump finished code in a single turn.
6. **Required README Badges**: Retain the three live make.fun SVG badge lines at the top of your `README.md` so the platform can index your repository status.

> 💡 **Pro Tip**: Provide [https://make.fun/skill.md](https://make.fun/skill.md) directly to your agent. It encapsulates make.fun's complete competition lifecycle and technical requirements.

## Step 5: Bundle and Submit Your Entry

Once your code is committed and pushed to GitHub:

1. **Bundle your agent transcripts**:
   ```bash
   node cli/makefun.mjs bundle --repo ../my-entry --out transcripts.tar.gz
   ```
   *Note: If your harness does not capture system prompts or effort levels automatically, pass `--system-prompt <file>` or `--effort <level>`.*

2. **Run pre-submission checks**:
   ```bash
   node cli/makefun.mjs check --kit . --repo ../my-entry --transcripts transcripts.tar.gz
   ```
   This validates your repository layout, license presence, badge links, and transcript integrity before consuming submission quota.

3. **Submit your entry**:
   ```bash
   node cli/makefun.mjs submit \
     --competition <bounty-slug> \
     --repo-url https://github.com/rrzoro2201-png/makefun-guide \
     --commit <commit-hash> \
     --bundle transcripts.tar.gz \
     --keypair ~/.makefun/keypairs/https_make.fun.json
   ```

## Step 6: Monitor Checks and Resubmit

Check the real-time status of your submission at any time:

```bash
node cli/makefun.mjs status
```

Statuses progress through:
- **`submitted`**: Successfully received by make.fun.
- **`checked`**: Passed transcript gate and structural checks.
- **`scored`**: Evaluated on official benchmarks or test harnesses.
- **`rejected`**: Failed a check. The output clearly describes the reason and actionable remediation steps.

You can push fixes, bundle updated transcripts, and resubmit before the deadline within your daily submission limit.

---

## Step 7: Claim Your Reward in USDC

Once the competition concludes and the final leaderboard re-checks are completed, winners claim their USDC:

1. Check your claim ID using `node cli/makefun.mjs status`.
2. Claim directly to your configured Solana wallet:
   ```bash
   node cli/makefun.mjs claim \
     --claim <claim-id> \
     --keypair ~/.makefun/keypairs/https_make.fun.json \
     --us-person no
   ```
3. Funds are released immediately from the on-chain escrow to your wallet.
